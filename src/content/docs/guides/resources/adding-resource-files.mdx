---
title: Adding resource files
description: Learn how to include external assets, game mods, and UI files using the file property.
---
The `file` property in your `resource.toml` manifest is used to specify which additional assets and client-side files need to be recognized, loaded, and streamed by the CyberMP server runtime.

In this guide, we will focus entirely on how to configure the `file` property to manage your resource assets.

## Understanding the `file` Property

   Any asset that your client script or UI page needs to access must be explicitly defined here. This includes custom game mods, map assets, 3D models, textures, and user interface files (HTML, CSS, JS for CEF).

   Here is an example configuration utilizing the `file` array:

   ```toml title="resource.toml"
   file = [
     "./assets/in_world_navigation.archive",
     "./assets/de_dust2/*",
     "./ui/*",
     "./ui/assets/*"
   ]
   ```

## Using Wildcard Patterns (`*`)

   Manually listing dozens of UI icons or map assets can quickly clutter your configuration file. To solve this, the `file` array supports wildcard matching using the `*` symbol.

   * `./ui/*` — Directs CyberMP to include every file sitting inside the root of the `browser` folder.
   > **Note:** Wildcard tracking is directory-specific. If you have subfolders inside a path (like a dedicated assets folder inside your browser UI), make sure to add a separate pattern for it, such as `./ui/assets/*`.

## Supported Asset Types vs. Scripting Files

   When you declare assets in the `file` array, CyberMP automatically loads them directly into the underlying game engine context at runtime.

   * **Supported Game Assets & Mods:** Custom archives, placement data, and engine tweaks such as `.archive`, `.xl`, `.tweak`, `.redscripts`, `.yaml` and `.yml` files are fully supported and injected directly into the game.
   * **Scripting Restrictions:** This automatic injection **does not apply** to standalone scripting files like `.js` (aside from frontend CEF scripts), `.lua`, or `.redscript`. Game-level scripts must be handled through `client_script` property of resource rather than the raw asset pipeline. (except for redscript files, these should be compiled and included into file property)
