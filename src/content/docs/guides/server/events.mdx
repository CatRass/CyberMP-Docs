The server-side event system manages game world lifecycles and coordinates communication across the network. It allows you to monitor player connections, track state changes like combat and vehicles, catch incoming client-side payloads, and broadcast data back out to connected players.

In this guide, you will learn how to structure and manage events on your server using either JavaScript or Lua.

---

## Platform & Custom Server Events

Use the event listener interface to hook into built-in game platform lifecycle events (such as players connecting, dying, or interacting with vehicles) as well as custom server-to-server events.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // 1. Platform Event: Handle new incoming player connections
    mp.events.on('playerConnected', (playerId, tempId) => {
      console.log(`Player connected - assigned Network ID: ${playerId}`);
    });

    // 2. Platform Event: Track player deaths and log combat analytics
    mp.events.on('playerDeath', (playerId, data) => {
      if (data.killerId) {
        console.log(`Player ${playerId} was flatlined by Killer ID: ${data.killerId}`);
      } else {
        console.log(`Player ${playerId} flatlined due to environmental damage.`);
      }
    });

    // 3. Custom Server Event: Triggered internally within server scripts
    mp.events.on('logServerActivity', (action, details) => {
      console.log(`[Activity Log] Action: ${action} | ${details}`);
    });

    // Emit the custom event inside your server environment
    mp.events.emit('logServerActivity', 'Database', 'Initial connection established.');
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- 1. Platform Event: Handle new incoming player connections
    mp.events.add('playerConnected', function(playerId, tempId)
      print(string.format("Player connected - assigned Network ID: %s", playerId))
    end)

    -- 2. Platform Event: Track player deaths and log combat analytics
    mp.events.add('playerDeath', function(playerId, data)
      if data.killerId then
        print(string.format("Player %s was flatlined by Killer ID: %s", playerId, data.killerId))
      else
        print(string.format("Player %s flatlined due to environmental damage.", playerId))
      end
    end)

    -- 3. Custom Server Event: Triggered internally within server scripts
    mp.events.add('logServerActivity', function(action, details)
      print(string.format("[Activity Log] Action: %s | %s", action, details))
    end)

    -- Emit the custom event inside your server environment
    mp.events.trigger('logServerActivity', 'Database', 'Initial connection established.')
    ```
  </TabItem>
</Tabs>

## Handling Packets from Clients

When client code transmits an event over the network socket using `emitServer` (JS) or `triggerServer` (Lua), the server catches it using `onClient` (JS) or `addClient` (Lua).

:::note
The server-side callback automatically receives the sending **player object** as the first argument, ensuring you always securely know which client initiated the request.
:::

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // Catching a vehicle spawn request from a client script
    mp.events.onClient('requestVehicleSpawn', (player, modelHash, x, y, z) => {
      console.log(`Player ${player.nickname} (${player.id}) requested to spawn: ${modelHash}`);

      // Your vehicle creation logic goes here...
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- Catching a vehicle spawn request from a client script
    mp.events.addClient('requestVehicleSpawn', function(player, modelHash, x, y, z)
      print(string.format("Player %s (%s) requested to spawn: %s", player.nickname or player.id, player.id, modelHash))

      -- Your vehicle creation logic goes here...
    end)
    ```
  </TabItem>
</Tabs>

## Emitting Events to Clients

To push messages, UI updates, or state sync packets across the network to players, you can either:

- Use `mp.events.emitClient(playerId, 'my-event', ...args)` in JS or `mp.events.triggerClient(playerId, 'my-event', ...args)` in Lua (specifying the target player by numeric ID or player reference).
- Call `player.emit('my-event', ...args)` in JS or `player:trigger('my-event', ...args)` in Lua directly on the target player object instance.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // Listen for a player spawning into the world
    mp.events.on('playerSpawn', (playerId) => {
      // Option 1: Direct a welcome alert using mp.events.emitClient
      mp.events.emitClient(playerId, 'serverNotification', 'Welcome back to Night City.');

      // Option 2: Direct a welcome alert calling emit directly on the player instance
      const player = mp.players.at(playerId);
      if (player) {
        player.emit('serverNotification', 'Welcome back to Night City.');
      }
    });

    // Example: Notifying a vehicle owner when their car is damaged
    mp.events.on('vehicleHittedByPlayer', (vehicleId, data) => {
      if (data.byOwner) {
        // Send an event back to the driver's client
        mp.events.emitClient(data.instigatorID, 'uiNotification', 'You damaged your own vehicle!');
      }
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- Listen for a player spawning into the world
    mp.events.add('playerSpawn', function(playerId)
      -- Option 1: Direct a welcome alert using mp.events.triggerClient
      mp.events.triggerClient(playerId, 'serverNotification', 'Welcome back to Night City.')

      -- Option 2: Direct a welcome alert calling trigger directly on the player instance
      local player = mp.players.at(playerId)
      if player then
        player:trigger('serverNotification', 'Welcome back to Night City.')
      end
    end)

    -- Example: Notifying a vehicle owner when their car is damaged
    mp.events.add('vehicleHittedByPlayer', function(playerId, data)
      if data[4] then
        -- Send an event back to the driver's client
        mp.events.triggerClient(playerId, 'uiNotification', 'You damaged your own vehicle!')
      end
    end)
    ```
  </TabItem>
</Tabs>

## Cancelling Platform Events

Certain game events (such as damage, explosion, or world state changes) can be intercepted and cancelled before they affect the game state. To cancel an event, you can return `false` from the callback function:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // Disable PvP damage in safe zones
    mp.events.on('damage', (victimId, data) => {
      const victim = mp.players.at(victimId);

      // If the victim is inside a designated safe zone
      if (victim?.getMeta('inSafeZone')) {
        return false;
      }
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- Disable PvP damage in safe zones
    mp.events.add('damage', function(playerId, data)
      local victim = mp.players.at(data.victimId)

      -- If the victim is inside a designated safe zone
      if victim and victim:getMeta('inSafeZone') then
        return false
      end
    end)
    ```
  </TabItem>
</Tabs>

## Cleaning Up Event Handlers

To prevent memory leaks or repeating routines when resources or modules restart, detach active event listeners using `off` in JS or `remove` in Lua (`remove` takes the listener id returned by `add`). This cleanup method works for both internal and network client listeners.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    // Define a named tracking handler function
    const trackExplosions = (playerId, data) => {
      console.log(`Explosion tracked at coordinate cluster: [${data.posX}, ${data.posY}]`);
    };

    // Register the active event listener hook
    mp.events.on('explosion', trackExplosions);

    // Unregister the handler when it is no longer required
    mp.events.off('explosion', trackExplosions);
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    -- Define a named tracking handler function
    local function trackExplosions(playerId, data)
      print(string.format("Explosion tracked at coordinate cluster: [%s, %s]", data.posX, data.posY))
    end

    -- Register the active event listener hook
    local explosionHandler = mp.events.add('explosion', trackExplosions)

    -- Unregister the handler when it is no longer required
    mp.events.remove('explosion', explosionHandler)
    ```
  </TabItem>
</Tabs>

## Communicating with CEF (Browser UI)

Using standard events, the server cannot communicate directly with a player's Chromium Embedded Framework (CEF) browser instance. Because CEF views run isolated within the local client environment, server-to-CEF communication routes through a client script bridge:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="server.js"
    mp.events.emitClient(playerId, 'browser:updateInventory', inventoryData);
    ```

    ```js title="client.js"
    mp.events.onServer('browser:updateInventory', (inventoryData) => {
      mp.events.emitCef('updateInventory', inventoryData);
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="server.lua"
    mp.events.triggerClient(playerId, 'browser:updateInventory', inventoryData)
    ```

    ```lua title="client.lua"
    mp.events.addServer('browser:updateInventory', function(inventoryData)
      mp.events.triggerCef('updateInventory', inventoryData)
    end)
    ```
  </TabItem>
</Tabs>

:::tip
Writing boilerplate proxy listeners on the client for every UI interaction can become repetitive. This limitation is solved by the Remote Procedure Call (RPC) system, which allows the server and CEF to invoke functions and exchange data directly.
:::
