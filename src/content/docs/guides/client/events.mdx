The client-side event system (`mp.events`) routes communication across three distinct targets: local scripts, the dedicated server, and the embedded Chromium Embedded Framework (CEF) user interface.

For full method signatures and event definitions, see the [`MpEvents`](/reference/client/api/events/mpevents/) and [`MpEventsMap`](/reference/client/api/events/mpeventsmap/) reference pages, or the [Lua Client Events reference](/reference/lua/client/#client-events-mpevents).

---

## Custom & Platform Events

Platform events are fired automatically by the client runtime when engine states transition (e.g., resources starting, entities streaming in). You can also emit custom local events to coordinate logic across scripts within the client:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    // Platform event: triggers when this client resource completes startup
    mp.events.on('resourceStart', () => {
      console.log('The client resource has successfully started.');
    });

    // Platform event: triggers when an entity enters streaming range
    mp.events.on('vehicleStreamIn', (netID, gameID) => {
      console.log(`Vehicle streamed in - NetID: ${netID}, GameID: ${gameID}`);
    });

    // Custom local event: listening for a local signal
    mp.events.on('myCustomEvent', (data) => {
      console.log('Received local data:', data);
    });

    // Emitting a custom local event
    mp.events.emit('myCustomEvent', { status: 'ok', timestamp: Date.now() });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    -- Platform event: triggers when this client resource completes startup
    mp.events.add('resourceStart', function()
      print('The client resource has successfully started.')
    end)

    -- Platform event: triggers when an entity enters streaming range
    mp.events.add('vehicleStreamIn', function(netID, gameID)
      print(string.format("Vehicle streamed in - NetID: %s, GameID: %s", netID, gameID))
    end)

    -- Custom local event: listening for a local signal
    mp.events.add('myCustomEvent', function(data)
      print('Received local data:', data)
    end)

    -- Emitting a custom local event
    mp.events.trigger('myCustomEvent', { status = 'ok', timestamp = os.time() })
    ```
  </TabItem>
</Tabs>

Stream events (such as `vehicleStreamIn` / `Out` and `remotePlayerStreamIn` / `Out`) pass both the server-assigned `netID` and local engine `gameID`. For identifier mapping outside of stream callbacks, see [Network IDs and Local Entities](/guides/client/network-and-local). For all built-in events, consult the [`MpEventsMap`](/reference/client/api/events/mpeventsmap/) reference.

## Communicating with the Server

Client scripts send data to the server using reliable network packets and listen for events dispatched from the server runtime:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    // Send a reliable packet to the server
    mp.events.emitServer('requestVehicleSpawn', 'Vehicle.v_sport1_quadra_turbo_r_player');

    // Listen for events dispatched from the server
    mp.events.onServer('serverNotification', (message) => {
      console.log(`[Server]: ${message}`);
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    -- Send a reliable packet to the server
    mp.events.triggerServer('requestVehicleSpawn', 'Vehicle.v_sport1_quadra_turbo_r_player')

    -- Send over unreliable channel (ideal for high-frequency input streams)
    mp.events.triggerUnreliable('playerInputTick', 30, { moving = true })

    -- Listen for events dispatched from the server
    mp.events.addServer('serverNotification', function(message)
      print(string.format("[Server]: %s", message))
    end)
    ```
  </TabItem>
</Tabs>

:::tip[Request-Response RPC]
When you need to wait for a return value from the server rather than listening for an asynchronous broadcast, use the [RPC system](/guides/recipes/rpc) (`RpcClient` / `RpcBrowser`).
:::

## Interacting with CEF (Browser UI)

Use CEF events to pass data between your client script and embedded HTML/CSS web interfaces:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    // Built-in CEF event: fires when the browser DOM is ready
    mp.events.onCef('domReady', (frameName) => {
      console.log(`Browser frame '${frameName}' is ready.`);

      // Send initial data to the CEF web page
      mp.events.emitCef('initializeDashboard', { playerName: 'V', health: 100 });
    });

    // Built-in CEF event: fires on uncaught JS errors in the browser
    mp.events.onCef('loadingFailed', (error) => {
      console.error(`CEF Load Failed: ${error.message} (Frame: ${error.frameName})`);
    });

    // Custom event: dispatched from the CEF page via mp.events.emit
    mp.events.onCef('uiAction', (actionName, payload) => {
      console.log(`User triggered UI action: ${actionName}`, payload);
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    -- Built-in CEF event: fires when the browser DOM is ready
    mp.events.addCef('domReady', function(frameName)
      print(string.format("Browser frame '%s' is ready.", frameName))

      -- Send initial data to the CEF web page
      mp.events.triggerCef('initializeDashboard', { playerName = 'V', health = 100 })
    end)

    -- Built-in CEF event: fires on uncaught JS errors in the browser
    mp.events.addCef('loadingFailed', function(error)
      print(string.format("CEF Load Failed: %s", tostring(error)))
    end)

    -- Custom event: dispatched from the CEF page via mp.events.emit
    mp.events.addCef('uiAction', function(actionName, payload)
      print(string.format("User triggered UI action: %s", actionName))
    end)
    ```
  </TabItem>
</Tabs>

CEF automatically dispatches two built-in events into every frame:
- **`domReady`**: Fires when the document structure has loaded (argument: `window.name`).
- **`loadingFailed`**: Fires on uncaught exceptions or unhandled promise rejections in the page (returns [`CefLoadingFailedError`](/reference/client/api/events/cefloadingfailederror/)).

To learn how to structure HTML interfaces and handle focus, see [Creating Your First CEF UI](/guides/client/first-cef-ui).

## Cleaning Up Listeners

To prevent memory leaks and duplicate callbacks across script reloads, detach listeners when they are no longer needed:

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    const handleVehicleStream = (netID, gameID) => {
      console.log(`Vehicle ${netID} streamed in.`);
    };

    // Register listener
    mp.events.on('vehicleStreamIn', handleVehicleStream);

    // Unregister listener
    mp.events.off('vehicleStreamIn', handleVehicleStream);
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    local function handleVehicleStream(netID, gameID)
      print(string.format("Vehicle %s streamed in.", netID))
    end

    -- Register listener (returns a handler token)
    local token = mp.events.add('vehicleStreamIn', handleVehicleStream)

    -- Unregister listener
    mp.events.remove(token)
    ```
  </TabItem>
</Tabs>

:::note[Listener Scope in JavaScript]
In JavaScript, `mp.events.off()` removes only listeners registered through `mp.events.on()`. Handlers registered through `onServer` or `onCef` use internal prefixes and are automatically cleaned up when the resource stops or restarts.
:::
