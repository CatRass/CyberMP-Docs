The observe API allows client scripts to listen to internal REDengine methods whenever they are invoked by the game engine. Observers act as passive listeners: they do not modify return values or prevent the underlying game function from executing.

For complete type signatures, see [`ObserveFunction`](/reference/client/api/global/observefunction/) and the [Lua Client Reference](/reference/lua/client/#method-hooks-observe--override).

---

## Registering an Observer

Register observers from the `onInit` lifecycle stage.

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    let settingsMenu = null;

    mp.game.onInit(() => {
      // Observe when the settings menu controller opens
      mp.game.observe('SettingsMainGameController', 'OnMenuChanged', (self) => {
        settingsMenu = self;
        console.log('Settings menu opened.');
      });

      // Observe when the settings menu controller requests close
      mp.game.observe('SettingsMainGameController', 'RequestClose', (self) => {
        settingsMenu = null;
        console.log('Settings menu closed.');
      });
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    local settingsMenu = nil

    mp.registerGameState('onInit', function()
      -- Observe when the settings menu controller opens
      mp.observe('SettingsMainGameController', 'OnMenuChanged', function(self)
        settingsMenu = self
        print("Settings menu opened.")
      end)

      -- Observe when the settings menu controller requests close
      mp.observe('SettingsMainGameController', 'RequestClose', function(self)
        settingsMenu = nil
        print("Settings menu closed.")
      end)
    end)
    ```
  </TabItem>
</Tabs>

## Method Signatures and Arguments

Class and method names correspond directly to definitions found in [NativeDB](https://nativedb.red4ext.com/).

- **Instance Methods:** The callback receives `(self, arg1, arg2, ...)`. The first argument is the instance of the game object executing the method.
- **Static Methods:** The callback receives `(arg1, arg2, ...)` without a `self` reference.
- **No Continuation Function:** Observers never receive `wrappedMethod`; it is appended only to overrides.
- **Overloaded Signatures:** If a method has multiple signatures in NativeDB, supply the full signature suffix (e.g. `'ClassName'`, `'MethodName;Int32Bool'`).
- **No Result Modification:** Observers receive `self` (for instance methods) and then the method arguments; they cannot alter return values or cancel function execution.

:::warning[Weak References]
The `self` reference passed into the callback is a weak pointer into the game engine's memory pool. Never assume a stored controller or entity reference remains valid once the corresponding entity or menu is closed or destroyed.
:::

## Execution Timing & Variants

The engine provides several observer variants to control capture timing and thread dispatching:

| Method Variant | Capture Point | Dispatch Behavior |
| :--- | :--- | :--- |
| `observe` / `observeBefore` | Before original method executes | Queued onto the script thread (runs on next tick) |
| `observeAfter` | After original method executes | Queued onto the script thread (runs on next tick) |
| `observeRaw` / `observeBeforeRaw` | Before original method executes | Dispatched immediately without tick queuing |
| `observeAfterRaw` | After original method executes | Dispatched immediately without tick queuing |

<Tabs syncKey={SCRIPT_LANG_TAB_SYNC_KEY}>
  <TabItem label="JS">
    ```js title="client.js"
    mp.game.onInit(() => {
      // Immediate raw capture of player input actions
      mp.game.observeBeforeRaw('PlayerPuppet', 'OnAction', (self, action) => {
        // Keep raw callback execution minimal and fast
      });
    });
    ```
  </TabItem>
  <TabItem label="Lua">
    ```lua title="client.lua"
    mp.registerGameState('onInit', function()
      -- Immediate raw capture of player input actions
      mp.observeBeforeRaw('PlayerPuppet', 'OnAction', function(self, action)
        -- Keep raw callback execution minimal and fast
      end)
    end)
    ```
  </TabItem>
</Tabs>

:::warning[Raw callbacks run on the game thread]
A raw observer runs synchronously inside the hooked game call, often on a job worker thread rather than the script thread, so the resource runtime is not freely available there. Keep raw callbacks to reading the arguments, and forward real work through the queued variants (`mp.observe`, `observeBefore`, `observeAfter`) or the client deferred queue (`setImmediate` in JS, `mp.setImmediate` in Lua).
:::

:::tip[Observer vs Override]
Observers cannot alter return values or prevent a game function from executing. If you need to intercept, replace, or block a game method, use [Method Overrides](/guides/client/overrides).
:::
