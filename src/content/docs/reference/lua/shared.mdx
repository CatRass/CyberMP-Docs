Shared Lua APIs are accessible on both the server and client runtimes, providing unified utilities for vector math, REDengine hash generation, entity metadata synchronization, coroutine task scheduling, and inter-resource exports.

---

## Vector Math

CyberMP provides three native vector constructors:
- `vector2(x, y)`: 2D vector (`.x`, `.y`)
- `vector3(x, y, z)`: 3D spatial coordinate (`.x`, `.y`, `.z`)
- `vector4(x, y, z, w)`: 4D coordinate / quaternion (`.x`, `.y`, `.z`, `.w`)

Components are represented as 32-bit floating-point numbers.

```lua title="shared.lua"
local pos = vector3(10.0, 20.0, 30.0)
local offset = vector3(0.0, 5.0, 0.0)
local combined = vector3(pos.x + offset.x, pos.y + offset.y, pos.z + offset.z)
```

## Numbers & Hashes (`mp.hashes`)

REDengine uses 64-bit unsigned integers (`uint64_t`) for TweakDB IDs, CNames, and Resource References.

Because standard numbers in many Lua configurations lose precision above $2^{53}$, CyberMP Lua hash helpers return hashes as **decimal strings** to prevent numerical corruption:

| Method | Context | Description |
| :--- | :--- | :--- |
| `mp.hashes.tweakdbid(str)` / `toTweakdbid(str)` | Server / Client | Resolves TweakDB item/vehicle records into decimal hash string. |
| `mp.hashes.cname(str)` / `toCname(str)` | Server / Client | Resolves entity appearance / bone names into decimal hash string. |
| `mp.hashes.resref(str)` / `toResref(str)` | Server / Client | Resolves resource file paths (`.ent`, `.mesh`) into decimal hash string. |
| `mp.hashes.fromTweakdbid(hash)` | Client (Natives) | Reverse lookup from hash string to TweakDB path. |
| `mp.hashes.fromCname(hash)` | Client (Natives) | Reverse lookup from hash string to CName string. |
| `mp.hashes.fromResref(hash)` | Client (Natives) | Reverse lookup from hash string to resource path. |

```lua title="shared.lua"
local carModelHash = mp.hashes.tweakdbid('Vehicle.v_sport1_quadra_turbo_r_player')
local skinHash = mp.hashes.cname('quadra_turbo_r__basic_player_01')

-- When passing hashes to client functions expecting numbers:
local numericHash = tonumber(carModelHash, 10)
```

:::note[Default Appearance]
For vehicles and NPCs, always pass `mp.hashes.cname('default')` if you do not require a specific visual variant.
:::

## Metadata Synchronization (`mp.meta`)

The metadata API provides key-value storage attached to global state, players, or entities. It avoids writing custom network packets for simple state synchronization.

### Setting & Getting Metadata

```lua title="shared.lua"
-- Global Meta: (key, value, syncOverNetwork)
mp.meta.setGlobal('serverWeather', 'rainy', true)
local weather = mp.meta.getGlobal('serverWeather')

-- Player Meta: (playerId, key, value, syncOverNetwork)
mp.meta.setPlayer(playerId, 'rank', 'admin', true)
local rank = mp.meta.getPlayer(playerId, 'rank')

-- Entity Meta: (entityId, key, value, syncOverNetwork)
mp.meta.setEntity(vehicleId, 'locked', true, true)
local isLocked = mp.meta.getEntity(vehicleId, 'locked')
```

- When `syncOverNetwork` is `true`, values automatically replicate from the server to all connected clients within streaming range.
- When `syncOverNetwork` is `false`, the value remains private to the environment that wrote it.

### Meta Change Events
When synced metadata changes, clients can react using change listeners:

```lua title="client.lua"
-- Triggered when global metadata changes
mp.events.add('globalMetaChange', function(key, newValue, oldValue)
  print(string.format("Global meta changed: %s = %s", key, newValue))
end)

-- Triggered when player metadata changes
mp.events.add('playerMetaChange', function(playerId, key, newValue, oldValue)
  print(string.format("Player %s meta updated: %s = %s", playerId, key, newValue))
end)

-- Triggered when entity metadata changes
mp.events.add('entityMetaChange', function(entityId, key, newValue, oldValue)
  print(string.format("Entity %s meta updated: %s = %s", entityId, key, newValue))
end)
```

## Task Scheduler & Timers

CyberMP provides cooperative scheduling for coroutines alongside interval timers:

### Millisecond Timer
- `mp.getTimer()`: Returns an integer millisecond counter elapsed since runtime start.

### Coroutine Sleep (`mp.wait`)
Inside coroutines or asynchronous task handlers, `mp.wait(ms)` pauses execution without blocking the main game thread:

```lua title="shared.lua"
local function countdownTask()
  for i = 5, 1, -1 do
    print("Countdown: " .. i)
    mp.wait(1000) -- Sleep for 1 second
  end
  print("Liftoff!")
end

-- Run in a coroutine
local co = coroutine.create(countdownTask)
coroutine.resume(co)
```

### Standard Interval Timers
```lua title="shared.lua"
-- Run repeating callback every 500ms
local timerId = mp.setInterval(function()
  print("Interval tick")
end, 500)

-- Run one-shot callback after 2000ms
local timeoutId = mp.setTimeout(function()
  print("Timeout triggered")
  mp.clearInterval(timerId)
end, 2000)
```

## Inter-Resource Exports (`mp.exports`)

Exports allow one resource to expose reusable functions to other resources on the same runtime side.

### 1. Declaring Exports in `resource.toml`

List exported function names in `resource.toml`:

```toml title="resources/banking/resource.toml"
server_script = 'server.lua'
export = ['getBalance', 'addFunds']
```

### 2. Implementing Exported Functions

Assign functions to the `mp.exports` table:

```lua title="resources/banking/server.lua"
mp.exports.getBalance = function(playerId)
  return 1500 -- Query database
end

mp.exports.addFunds = function(playerId, amount)
  print(string.format("Added %s funds to player %s", amount, playerId))
  return true
end
```

### 3. Calling Exports from Another Resource

Access functions through `mp.resources[resourceName]`:

```lua title="resources/shop/server.lua"
mp.commands.add('balance', function(player, args)
  local balance = mp.resources.banking.getBalance(player.id)
  player:emit('chat:addMessage', string.format("Current Balance: $%s", balance))
end)
```

:::important[Load Order]
Resources that provide exports must be listed **before** dependent resources in the `resources` array of `server.toml`.
:::
